# 节点与安装实例重构 R0：删除清单与新表/契约

> 状态：R0 设计定稿，未改动代码。
> 适用阶段：平台与老客户端均未上线、授权均为测试授权；允许删库重建。
> 目标：把“物理机 / 应用安装 / 应用域”三个概念彻底拆开，后续 R1–R5 不再靠补丁兼容旧模型。

## 0. 术语与唯一口径

| 术语 | 定义 | 唯一事实源 |
|---|---|---|
| 节点 Node | 一台物理机，由主板/SMBIOS 派生的全局机器码标识 | `device_nodes.machine_code` |
| 安装实例 Installation | 某个应用（`appKey`）在某节点上的一次客户端安装 | `device_installations (app_key, install_guid)` |
| 应用 App | 业务隔离轴，对应产品线与权限域 | `apps.app_key` |
| 席位 Seat | 某产品在某节点上的一份有效授权 | `license_entitlements (product_id, machine_code)` |
| 会话 Session | 一条刷新令牌；可关联应用、机器码、安装 Guid | `refresh_tokens` |

关系：

```text
device_nodes (1) ──< device_installations (N)
       │                        │
       │ machine_code           │ app_key
       ▼                        ▼
license_entitlements          apps
(product_id, machine_code)
```

三条硬边界：

1. **机器码只属于节点**，全局唯一；不再按 `appKey` 各存一份设备事实。
2. **安装实例只属于一个应用**；在线/工位/报警/版本分支/命令回执都落在安装实例上。
3. **授权席位按“产品 + 机器码”计数**，不按安装实例计数；一台机器装 3 个产品就是 3 个席位。

## 1. 不可变设计决策

| 编号 | 决策 | 说明 |
|---|---|---|
| D1 | 机器码 = `SHA-256("AF-MACHINE\|" + 规范化主标识)` 前 10 字节，Crockford Base32 16 字符 | 与现平台算法一致；老客户端 SMBIOS 口径为准 |
| D2 | 主标识只接受 SMBIOS UUID，缺失时接受系统盘序列号；两者都没有则拒绝注册 | 删除 InstallGuid / MAC / MachineGuid 回退；不再生成“假机器码” |
| D3 | 节点全局唯一，表上不再有 `app_key` | 同一台机器在 3 个应用里是 1 个节点、3 个安装实例 |
| D4 | 安装实例唯一键 = `(app_key, install_guid)` | 同机不同应用互不覆盖；同一应用重装会产生新安装实例（旧实例保留为历史） |
| D5 | 一个安装实例同一时刻只保留一个活跃 Hub 连接 | 同安装重连/重装顶替旧连接；不同安装实例互不顶号 |
| D6 | 授权席位唯一键 = `(product_id, machine_code)`，产品本身按 `app_key` 隔离 | 3 个产品 = 3 条授权；同一产品重装/换安装不增加席位 |
| D7 | 离线授权码升级为 **AF4**，payload 增加 `appKey` | 防止应用 A 的离线码在应用 B 被接受；AF3 不再解析 |
| D8 | 节点名 = 客户端机器名（`auto_name`）+ 管理端 `custom_name`；安装实例名 = 应用内录入名（`client_name`）+ 管理端 `custom_name`；版本分支、框架版本归安装实例 | 管理端按“物理节点为主、应用为子标签”展示，应用内录的名字不再污染节点 |
| D9 | 节点启用是全局开关；安装实例启用是应用级开关 | 有效启用 = 节点启用 && 安装实例启用 |
| D10 | 节点在线/工位状态不落列，由安装实例聚合 | 避免多应用心跳互相覆盖造成“最后一个上报者赢” |
| D11 | 节点级重启发到节点组，安装级重启发到安装组 | 命令目标不再“发给共享设备记录，所有安装都收到” |
| D12 | `device.*` 权限码、`/admin/devices` 路由、`DeviceKey` 字段全部淘汰 | 新语义：`node.*` / `installation.*`；不保留兼容别名 |
| D13 | 不双写、不迁移旧数据、不留旧列；迁移历史压成一个基线 | 测试库直接重建；旧迁移与快照全部删除 |
| D14 | 新客户端暂停接入 | 其 `MachineGuid` 派生机器码与老客户端不一致；平台稳定前不注册、不发版 |

## 3. 新表结构契约

> PostgreSQL。时间列统一 `timestamptz`；C# 侧仍是 `DateTimeOffset`。
> 所有表沿用 `IAuditableEntity` 的 `created_at` / `updated_at`。

### 3.1 `device_nodes`（物理节点）

```sql
CREATE TABLE device_nodes (
    id              uuid        NOT NULL,
    machine_code    varchar(32) NOT NULL,
    auto_name       varchar(128),
    custom_name     varchar(128),
    display_name    varchar(256) NOT NULL,
    ip_address      varchar(64),
    is_enabled      boolean     NOT NULL DEFAULT TRUE,
    first_seen_at   timestamptz,
    last_seen_at    timestamptz,
    created_at      timestamptz NOT NULL,
    updated_at      timestamptz NOT NULL,
    CONSTRAINT pk_device_nodes PRIMARY KEY (id)
);

CREATE UNIQUE INDEX ux_device_nodes_machine_code
    ON device_nodes (machine_code);
CREATE INDEX ix_device_nodes_last_seen
    ON device_nodes (last_seen_at DESC);
```

字段口径：

| 字段 | 写入规则 |
|---|---|
| `machine_code` | 注册时由服务端计算；客户端不能自报 |
| `auto_name` | 客户端注册上报的机器名，每次注册刷新 |
| `custom_name` | 只由管理端写入（含清空）；客户端注册不得覆盖，应用内录入的名称写在安装实例上 |
| `display_name` | `custom_name` 非空取自定义名，否则取 `auto_name`，都为空取 `machine_code` |
| `ip_address` | 任一安装实例注册/心跳上报的最近 IP |
| `is_enabled` | 节点总开关；停用后该机器所有应用拒绝注册/心跳 |
| `first_seen_at` / `last_seen_at` | 节点首次/最近一次被任一安装实例注册或心跳 |

**不落节点状态列**。节点在线/工位/报警按下述口径实时聚合：

```sql
-- 节点在线：任一安装实例在线
EXISTS (SELECT 1 FROM device_installations i
        WHERE i.node_id = n.id AND i.online_status = 'online')

-- 节点运行中：任一安装实例在线且工位运行
EXISTS (SELECT 1 FROM device_installations i
        WHERE i.node_id = n.id AND i.online_status = 'online' AND i.station_status = 'online')

-- 节点待机：在线且没有任何安装实例运行
NOT EXISTS (... station_status = 'online')
```

节点报警取安装实例中最严重级别（`error > warning > info > none`），同级取最近心跳。

### 3.2 `device_installations`（应用安装实例）

```sql
CREATE TABLE device_installations (
    id                uuid        NOT NULL,
    node_id           uuid        NOT NULL,
    app_key           varchar(64) NOT NULL,
    install_guid      uuid        NOT NULL,
    client_name       varchar(128),
    custom_name       varchar(128),
    display_name      varchar(128),
    branch            varchar(64),
    framework_version varchar(64),
    online_status     varchar(16) NOT NULL DEFAULT 'offline',
    station_status    varchar(16) NOT NULL DEFAULT 'idle',
    alarm_level       varchar(16) NOT NULL DEFAULT 'none',
    alarm_message     varchar(512),
    first_connected_at timestamptz,
    last_connected_at  timestamptz,
    last_heartbeat_at  timestamptz,
    heartbeat_seconds  integer     NOT NULL DEFAULT 10,
    is_enabled         boolean     NOT NULL DEFAULT TRUE,
    created_at         timestamptz NOT NULL,
    updated_at         timestamptz NOT NULL,

    CONSTRAINT fk_device_installations_node
        FOREIGN KEY (node_id) REFERENCES device_nodes (id)
        ON DELETE RESTRICT
);

CREATE UNIQUE INDEX ux_device_installations_app_install
    ON device_installations (app_key, install_guid);
CREATE INDEX ix_device_installations_node
    ON device_installations (node_id);
CREATE INDEX ix_device_installations_app_heartbeat
    ON device_installations (app_key, last_heartbeat_at DESC);
CREATE INDEX ix_device_installations_app_online
    ON device_installations (app_key, online_status);
```

字段口径：

| 字段 | 写入规则 |
|---|---|
| `app_key` | 只来自 JWT 的 `app` 声明；不接受客户端传参 |
| `install_guid` | 客户端首次安装生成并持久化；同一应用重装会变化 |
| `client_name` | 应用内录入的安装实例名称（`DeviceRegistrationRequest.customName`），每次注册刷新 |
| `custom_name` | 只由管理端写入（含清空）；客户端注册不得覆盖 |
| `display_name` | `custom_name` 非空取自定义名，否则取 `client_name`；都为空时管理端按 `short_id` 展示 |
| `branch` / `framework_version` | 当前安装实例上报；不同应用可不同 |
| 在线/工位/报警 | 全部按安装实例独立维护，不再互相覆盖 |
| `first_connected_at` | 该安装实例首次注册时间 |
| `last_connected_at` | 最近一次 Hub 注册时间 |
| `last_heartbeat_at` | 服务端时间；离线扫描依据 |
| `heartbeat_seconds` | 1–3600；未上报取平台默认 |
| `is_enabled` | 应用级开关；与节点开关同时为真才有效 |

注册 upsert 顺序：

1. 按 `machine_code` 查/建 `device_nodes`。
2. 校验节点 `is_enabled`。
3. 按 `(app_key, install_guid)` 查/建 `device_installations`。
4. 校验安装实例 `is_enabled`（重装产生的新行默认启用；旧安装行单独停用不影响新行）。
5. 更新节点 `auto_name`（机器名）/IP/`last_seen_at`，更新安装实例 `client_name`（应用内录入名）与运行时字段；
   两侧的 `custom_name` 与 `display_name` 都不被客户端注册覆盖。
6. 返回 `InstallationId` + `NodeId`。

> **不修改 `install_guid`**：`install_guid` 就是安装实例唯一键的一部分，同一应用重装后是新 Guid，
> 因此第 3 步必然查不到旧行、生成新安装实例（见 D4 与 §6.3）。旧行保留为历史，不会改名或合并。
> 并发首次注册由 `ux_device_installations_app_install` / `ux_device_nodes_machine_code` 兜底，
> 冲突后清跟踪按两条唯一键重试（最多两次）。

> 重装语义：旧安装实例行不会删除；备份、审计仍可追溯。管理端默认按 `last_heartbeat_at` 排序，可停用旧实例。自动归档不在 R1 范围。

```csharp
DevicesPrimaryIdentifierMissing  = 808,
DevicesNodeNotFound              = 809,
```

- `DevicesNotFound` 不再作为主错误；节点/安装实例分别返回明确错误。

## 6. 验收标准：一台机器 3 个应用

### 6.1 数据形态

同一台机器（同一 SMBIOS UUID）先后启动 `app-a`、`app-b`、`app-c` 三个客户端：

| 表 | 期望 |
|---|---|
| `device_nodes` | 1 行；`machine_code` 相同 |
| `device_installations` | 3 行；`node_id` 相同，`app_key` 分别为三个应用 |
| `license_entitlements` | 每个产品 1 行；共 3 行；`machine_code` 相同 |
| `refresh_tokens` | 每个应用会话各 1 行；`app_key` 正确，`machine_code` 相同，`install_guid` 各自不同 |

### 6.2 API/UI 断言

1. `GET /api/v1/admin/nodes` 只返回 1 个节点；`installationCount = 3`，`appKeys` 含三个应用。
2. 节点详情按应用分组显示 3 个安装实例；每个应用标签下只显示自己的安装。
3. `GET /api/v1/admin/installations`（应用 A 令牌）只返回应用 A 的 1 条安装实例。
4. 应用 A 重启只让应用 A 收到 `Restart`；应用 B/C 连接不收到。
5. 节点重启让 3 个安装实例都收到 `Restart`。
6. 停用节点后，三个应用注册/心跳均返回 `DevicesNodeDisabled`。
7. 停用应用 A 的安装实例后，A 返回 `DevicesInstallationDisabled`；B/C 不受影响。
8. 会话列表显示 `appKey`、`machineCode`、`installGuid`、`nodeId`、`nodeName`；同一机器三条会话不再混为一条。
9. 授权列表三条记录的机器码相同、产品不同；节点页可按机器码看到三条授权。
10. 离线码：应用 A 的产品码在应用 B 校验必须失败（`AppKey` 不匹配）。
11. 备份列表显示 `installationId`、`nodeId`、`nodeName`；节点页能按节点查看三个应用的备份。
12. 仪表盘显示 1 个节点、3 个安装实例，不再把同一台机器按应用重复计成 3 台“设备”。

### 6.3 重装场景

1. 应用 A 重装，`installGuid` 变化，`machine_code` 不变。
2. `device_nodes` 仍 1 行。
3. 应用 A 新增一条安装实例；旧实例保留为历史，`last_heartbeat_at` 不再更新。
4. 授权席位不增加（产品 + 机器码未变）。
5. 应用 A 的连接被新安装顶替；应用 B/C 连接不受影响。

### 6.4 缺失主标识场景

1. 客户端既取不到 SMBIOS UUID，也取不到系统盘序列号。
2. 注册返回 `DevicesPrimaryIdentifierMissing`。
3. 平台不生成节点、不生成授权可用机器码。
4. 客户端提示“无法读取主板/硬盘标识，请联系管理员”，而不是伪造机器码。

# 管理台响应式四档验收清单（B12-4）

适用对象：`web/` 管理台（React 18 + Ant Design 5）。口径来自
`docs/平台功能完善_全模块审计与响应式计划.md` §5，代码实现集中在 `web/src/shared/responsive.ts`
与 `web/src/app/AppShell.tsx`。

## 1. 自动化部分

| 项 | 命令 | 覆盖 |
|---|---|---|
| 纯策略单测 | `node ./node_modules/vitest/vitest.mjs run` | `resolveResponsiveInfo`（360/768/1024/1440 判定）、`resolveNavLayout`（drawer/icon/full）、`responsiveWidth`、`responsivePagination` |
| 类型 | `node ./node_modules/typescript/bin/tsc --noEmit` | `TableColumnsType` 的 `responsive`、分页回调签名 |
| 静态门禁 | `node ./node_modules/eslint/bin/eslint.js src --ext .ts,.tsx` | 未使用导入、Hooks 依赖 |
| 全量门禁 | `npm run verify` | 上述三项 + token 检查 |

jsdom 组件测试依赖离线环境装不上，B12-4 先用 node 环境的纯策略测试兜住
宽度/导航/分页决策，视觉与交互走下面的人工四档清单。

## 2. 四档宽度

| 宽度 | 设备/场景 | 预期 |
|---|---|---|
| 360 | 手机扫码审批、单次密钥 | 侧栏为 Drawer（≤86vw）可开合；无页面级横向滚动；弹窗/抽屉整宽；筛选输入不溢出；表格横滚且操作列固定在右侧可达；分页单行 simple；长哈希/机器码换行不撑破 |
| 768 | 平板/窄窗 | 侧栏 64px 图标栏；Header 应用上下文选择器不换行挤压；表格操作列可达；次要列仍隐藏（`responsive:['md']` 在 768 命中，需确认不产生横向滚动） |
| 1024 | 小笔记本 | 216px 常驻侧栏；详情抽屉半屏（760/860）；主要业务表无需横向滚动 |
| 1440 | 工位显示器 | 内容区居中最宽 1320px；卡片/表格不拉满；Descriptions 2–3 列；统计与详情留白均衡 |

> 768 档注意：antd `md` 在 ≥768 生效，因此次要列在 768 会出现；若某业务表在 768 出现
> 页面级横向滚动，优先把该列改回详情抽屉，而不是继续加宽表格。

## 3. 逐页检查项

通用项（每页都过）：

- [ ] Header 右侧的应用上下文切换可用；切换后本页筛选条件清空、回第一页。
- [ ] 列表页有刷新按钮；请求失败出现错误提示且带「重试」。
- [ ] 表格 `scroll={{ x: 'max-content' }}`，操作列 `fixed: 'right'`。
- [ ] 次要列（创建时间、说明、哈希、备注）在 360 下隐藏或换行。
- [ ] 服务端分页列表在 360 下为 simple 分页，无 size changer。
- [ ] 弹窗/抽屉在 360 下不超屏，表单行可换行，关闭按钮可达。

| 页面 | 额外检查 |
|---|---|
| 登录 / 首次改密 | 360 下表单不溢出；6 位口令输入框不撑破 |
| 总览 | 1440 内容居中；模块表横滚时模块键列不挤压 |
| 应用接入 | 360 下应用键 `code` 可换行；密钥抽屉整宽；明文密钥 `break-all` |
| 版本管理 | 渠道表短列表；发布表分页可翻页；创建发布弹窗（840/整宽）文件行可换行；详情抽屉（760/整宽）包表与文件表操作列可达 |
| 更新器 | 上传弹窗整宽；下载按钮在操作列内可达 |
| 身份-用户/会话 | 筛选行换行；会话指纹省略号悬停可见；分页 simple |
| 身份-角色 | 权限 Tag 换行；角色弹窗（720/整宽）作用域与权限树可滚动 |
| 身份-扫码审批 | 360 下卡片列表代替表格；倒计时不换行错位；批准弹窗整宽 |
| 文档 | 集合/文档两级筛选换行；详情抽屉整宽；SHA-256 与修订路径 `break-all` |
| 备份 | 命名空间表横滚；新建备份弹窗（640/整宽）版本行换行；下发弹窗整宽 |
| 授权 | 三个 Tab 的分页都走服务端；机器码/授权码 `break-all`；离线码弹窗输出 `pre-wrap`；密钥指纹省略号 |
| Webhook | 接收地址省略号悬停；投递台账分页 simple；展开行负载 `break-all`；轮换/删除按钮在操作列 |
| 审计 | 筛选行换行；时间与操作者列 360 隐藏；详情长字段换行 |

## 4. 浏览器手工步骤（需可运行 API + PostgreSQL）

本机 PostgreSQL 可用时按此节执行（2026-11-13 已跑通）；没有 PostgreSQL/Docker 时改用内网测试机
`vlxcnczbmqttp01` 或 CI 的 Testcontainers 环境。

1. `dotnet run --project src/Platform.Api` 启动 API（用编译产物时先 `cd src/Platform.Api/bin/Release/net10.0`
   再启动 DLL，否则内容根落在仓库根、读不到 `appsettings.Development.json`），另起 `npm run dev` 启动管理台。
   连接串用 `ConnectionStrings__Platform` 环境变量覆盖到本机库，Development 下自动迁移并种子管理员。
2. Chrome DevTools → Device Toolbar，依次设 360×800、768×1024、1024×768、1440×900。
3. 每档按第 3 节逐页过；重点看：外壳导航、Header 上下文切换、筛选行、表格操作列、分页、弹窗/抽屉。
4. 断网或改错 API 地址，确认每个列表都出现错误提示且「重试」可恢复。
5. 键盘 Tab 走一遍纯图标按钮（刷新、主题、折叠/展开、退出、重投），确认可聚焦且读屏有名称。

发现问题时优先改 `responsive.ts` 或共享组件；单页特例才在页面内用 `isMobile` 兜底。

## 5. 回归记录（2026-11-13）

环境：本机 PostgreSQL（127.0.0.1:5432，库 `appframework_platform`）+ Release 构建的
`Platform.Api.dll`（127.0.0.1:5080）+ Vite dev（127.0.0.1:5199），CDP 模拟四档视口。

- 12 条路由 × 4 档宽度：页面级横向溢出 0（`documentElement.scrollWidth <= clientWidth`）。
- 360：导航为 310px Drawer（86vw），12 个菜单项、遮罩与关闭可用，Sider 不渲染。
- 768：Sider 64px 折叠；1024/1440：Sider 216px；1440 内容区居中且不超过 1320px。
- 业务表操作列均命中 `fixed:'right'`；360 下身份、版本页分页为 simple 且无 size changer。
- 360 弹窗宽 344px（左右各留 8px），版本详情抽屉整宽 360px；768 弹窗 520px、抽屉 760px；
  弹窗/抽屉均不产生页面或 body 级溢出。
- 阻断 `/api/v1/admin/audit*` 后审计页出现错误提示与「重试」，恢复后点击重试错误消失并加载 20 行。
- 1024 及个别 1440 页面的宽表内部仍可横滚（总览模块表约 1423px），符合 §5.3
  `scroll x=max-content` + 操作列固定的设计，不影响页面级布局。

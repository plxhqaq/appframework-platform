## 0. 结论先行：前提修正

「安装实例靠 HTTP 轮询连接平台、需要改成 WebSocket」这一前提**已过时**。现状：

- 安装实例 ↔ 平台的连接**已经是 SignalR（默认传输即 WebSocket）**：`/hubs/devices`，注册 / 心跳 / 工位上报 / 配置下发 / 远程重启 / 顶号通知全部走长连接（`src/Platform.Modules.Devices/Hubs/DeviceHub.cs`，`Program.cs:301` 挂载）。
- 老客户端 `ServerGateway`（`AppFrameworkCS/client/AppFramework.Communication.Server/ServerGateway.cs`）已完成对接：换 M2M 令牌 → 连 Hub → 注册 → 10s 心跳 → 指数退避重连（5s 起、封顶 5min）。
- nginx 已配好 `/hubs/` 的 WebSocket 透传（Upgrade/Connection 头 + 3600s 读写超时，`deploy/nginx/site.d/web.conf.http`）。

**真正的缺口是「事件面」与「连接生命周期」**，本设计的改造主题是在既有 SignalR 通道上补齐它们，而不是更换传输层：

1. 实例定向事件缺失：授权变更只广播到 `/hubs/platform` 的应用组，设备 Hub 收不到，老客户端靠 **6 小时**周期复检发现吊销；版本发布 / 文档变更事件契约已定义但**服务端无发送者**；权限清单变更、会话吊销、节点/实例停用**完全无通知**（停用后已建立的连接甚至不被断开）。
2. 管理台 web 无任何实时通道：节点/安装页纯手动刷新，仪表盘 10s、下发选择器 15s、扫码审批 5s 轮询。
3. 安全与隔离缺陷：`PlatformHub` 无 `[Authorize]`；扫码审批结果 `Clients.All` 全网广播（`QrLoginService.cs:531`），未按应用/会话隔离。
4. 长连接与令牌生命周期脱钩：M2M 令牌 30min 过期、无刷新令牌，但 SignalR 连接建立后不再校验令牌——过期令牌 / 已停用应用的连接可以无限期存活并继续收推送。用户访问令牌同样可被无限自续期：`/context` 仅凭访问令牌即可换发新 30min 令牌（评审核验，见 §12），会话吊销对不配合的客户端实际无效。

## 1. 现状架构速览

### 1.1 双 Hub 与消费方

| Hub | 路径 | 鉴权 | 分组 | 现有事件 | 实际消费方 |
|---|---|---|---|---|---|
| DeviceHub | `/hubs/devices` | `[Authorize]` + 令牌 `app_ctx` | `installation:{id}`、`node:{id}` | 下行 `ConfigPush / Restart / SessionReplaced`；上行 `RegisterInstallation / Heartbeat / ReportStationState / AcknowledgeConfigPush` | 老客户端 ServerGateway |
| PlatformHub | `/hubs/platform` | **无 `[Authorize]`**（无 app 声明不入组但可连） | `app:{appKey}` | `LicenseChanged / QrLoginApproved / ConfigPush(broadcastToApp)`；`ReleasePublished / DocumentChanged` 契约预留无发送者 | **无人消费**（老客户端不连此 Hub）→ **本轮整体删除（D2/D11）** |

事件契约集中在 `src/Platform.Contracts/Hubs/PlatformHubs.cs` 与 `src/Platform.Contracts/Devices/DeviceContracts.cs:373-415`。

### 1.2 连接生命周期与在线判定

- 监督循环（客户端）：换令牌 → 连 Hub → `RegisterInstallation` 首帧注册 → 心跳循环；断线指数退避；`ConnectAsync` 只发起不等待。
- 顶号规则（R0-D5）：同一安装实例同一时刻只保留一条活跃连接；同节点同应用旧安装随新安装作废；跨应用并存（`InstallationConnectionRegistry`，进程内单例）。
- 在线判定三重：心跳落库（`InstallationPresence`，服务端时间）→ 最后一条连接断开立即离线（`DeviceHub.OnDisconnectedAsync`，带时间锚点防覆盖）→ 离线扫描兜底（`InstallationOfflineWorker`，阈值 `max(心跳×3, 60s)`，30s 一轮）。
- 命令下发在线判定 = 库 `online_status=online` **且** 连接登记表有活跃连接（`InstallationCommandGateway.cs:57-59`）。
- 节点在线/工位/报警不落列，由安装实例实时聚合（R0-D10，`InventoryMapper`）。

### 1.3 推送语义（不可动摇的既有约定）

**所有推送都只是提示，客户端收到后必须回拉 HTTP 接口重新校验，推送不得作为事实来源**（`Program.cs:79-80`、`PlatformHubs.cs:18-21`、11-devices.md）。授权结论以签名快照（AFLIC2，ECDSA P-256）验签为准。本设计全部沿用。

### 1.4 鉴权与令牌

- 安装实例：`X-App-Key + X-Api-Key` → `POST /api/v1/apps/token` 换 M2M 服务令牌（30/min 限流），JWT 30min、**无刷新令牌**、`pkind=service`、`app_ctx=appKey`。
- `access_token` 查询参数只对 `/hubs/devices` 放行（`AuthenticationSetup.cs:49-58`）；浏览器连 `/hubs/platform` 需 negotiate 带 Authorization 头。
- `AppContextGuardMiddleware` 只拦 HTTP 请求路径（应用停用 30s 短缓存），**不覆盖已建立的 Hub 连接**。
- 用户会话：刷新令牌家族制、一次一换、复用检测吊销全家族（`RefreshTokenService`）；访问令牌自包含 30min，吊销刷新令牌后访问令牌在有效期内仍可用。**且 `/context` 仅凭访问令牌即可换发新访问令牌**（`AdminAuthEndpoints.cs:173` 只 `RequireAuthorization()`；`IdentityAuthService.cs:168-177` 刷新令牌可选）——残余令牌可无限自续期，D7 的 epoch 守卫即为此而设。

### 1.5 部署与扩容边界

- Kestrel 恒听 8080 明文 HTTP，TLS 在 nginx；设备端明确不走 https（自签证书不信任）。
- **单副本硬约束**：连接登记表、Ack 等待表（`InstallationCommandAcks`）、推送协调器（`PlatformPushCoordinator`）全是进程内状态；PG advisory lock（`SingleInstanceGuard`，`Program.cs:243-263`）把第二副本挡在启动阶段。

## 3. 设计决策（D1–D11）

**D1 保留 SignalR，不换裸 WebSocket、不引入 MQTT。**
注册/顶号/分组/Ack 等待/离线判定/ nginx 透传 /客户端 SDK 全部已就位且经联调；裸 WS 需要自建全部这些机制，纯负收益。MQTT（MQTTnet）是现场设备数据上传通道，与平台管理面不同轴，不复用其连接。

**D2 双 Hub 按消费方与鉴权轴拆分；PlatformHub 整体删除。**（评审后按 D11 零兼容修订）

| Hub | 消费方 | 鉴权轴 | 事件方向 |
|---|---|---|---|
| `/hubs/devices`（既有） | 安装实例（M2M 服务令牌） | `app_ctx` + 连接登记表归属 | 实例定向 + 应用广播 |
| `/hubs/admin`（新增） | 管理台浏览器（管理员令牌） | `[Authorize]` + 权限域分组 | 管理视图事件 |

理由：两类消费方的令牌种类、分组轴、事件集合完全不同，分 Hub 门禁清晰。原 `/hubs/platform` 零消费方，其三个发送方（Licensing/QR/Backup 广播）全部改道 devices + admin 后，Hub 本体、路径/分组/事件常量与 `ConfigPushNotification/ConfigPushAck` DTO 一并删除（§4.3）——无鉴权 Hub 的存在本身就是攻击面，测试期直接移除而非加固保留。

**D3 推送仍是提示，回拉才是事实；不引入持久 outbox / 消息队列。**
单副本 + 提示语义下，断线窗口丢失的事件由「重连对账」覆盖（§6），无需逐事件持久化与投递重试。保持架构简单，与既有约定一致。

**D4 DeviceHub 增加 `app:{appKey}` 分组，实例所需事件全部收敛到 devices Hub。**
注册成功时把连接加入应用组。广播类事件（版本/文档/权限清单/配置广播）发 app 组，定向类（授权/停用/会话吊销）发 installation 组。客户端一条连接收齐所有事件。统一规则：**实例/用户会话事件一律走 devices + admin 两路，platform Hub 删除（D2）**；`broadcastToApp` 配置广播能力保留但改道 devices app 组（回执语义不变，§5.4）。顶号与作废路径必须同步把旧连接移出 app 组（现有代码只清 installation/node 组，`DeviceHub.cs:119-146`），否则被顶替连接断开前仍会收到应用广播。通知 DTO 随 `PlatformHubs.cs` 删除整体归位到各域契约（Devices/Identity），零兼容包袱下不留旧命名空间（D11）。

**D5 授权变更定向路由：`(appKey, machineCode)` → 节点 → 该应用活跃安装实例。**
授权席位键是 `(product, machineCode)`，吊销/续期影响的是「那台机器上那个应用」的所有安装实例。路由实现：查 `device_nodes` 拿 nodeId → 连接登记表筛 `appKey + nodeId` 的活跃连接 → 逐 installation 组发送。不向 node 组整组广播（避免同机其它应用的安装实例收到无关提示）。离线实例不补发——上线注册后由重连对账覆盖。

**D6 连接生命周期守卫用 Hub 过滤器实现，不新增后台扫描。**
新增 `DeviceHubGuardFilter`（`IHubFilter`）拦截每次上行调用，检查：
1. 令牌 `exp` 声明已过期 → `Context.AbortConnection()`；
2. 连接登记表上该连接/实例/节点带「停用待踢」标记 → 先送 `InstallationDisabled/NodeDisabled` 事件再 `AbortConnection()`。
心跳默认 10s 一次，故过期/停用检测延迟 ≤ 一个心跳周期。客户端监督循环自动换令牌重连；被停用者重连注册被拒（806/807）进入退避，不会风暴。`AbortConnection` 是服务端强制断线，不依赖客户端配合，恶意/旧版客户端同样被踢。

**D7 会话吊销 = 吊销刷新令牌家族 + 用户级令牌 epoch 守卫 + 推送 + 客户端主动登出；不引入 jti 黑名单。**（评审修订，原案「接受 ≤30min 残余窗口」被证伪，见 §12）

- 原案假设「残余访问令牌至多再活 30min」不成立：`/context` 仅凭访问令牌即可换发新 30min 令牌（刷新令牌可选），被吊销者可无限自续期；QR 审批（只需 `IdentityQrApprove` 权限）还可用残余令牌给自己签发临时会话。
- 修订：`users` 加 `token_epoch` 列（int），JWT 加 `epoch` 声明；吊销会话 / 重置口令 / 改密时 bump（收口在 `RefreshTokenService` 吊销路径）。复用 `AppContextGuardMiddleware` 模式新增**用户级短缓存（30s）守卫中间件**：请求令牌 epoch 落后于库值即 401。成本 = 一列 + 一声明 + 一个中间件，每活跃用户至多 30s 一次查库，与既有应用级守卫同量级。
- 效果：残余窗口从「无上界」收敛到 **≤30s**，全局覆盖所有续期路径（/context、QR 审批、单次密钥签发）；推送 + 主动登出仍是体验层（≤5s），守卫是强制兜底。
- `UserSessionRevoked` 按吊销范围定向（单会话→对应 installGuid 的安装组；用户全部会话→该用户涉及的安装组），客户端收到后回拉确认并清本地会话。epoch 为**用户级**：吊销任一会话即 bump，该用户全部访问令牌在 ≤30s 内失效——比家族级更严格，符合「吊销即踢」的管理语义。
- AdminHub 是纯下行通道，D6 的「搭载上行调用检查」对其失效：新增轻量上行 `Touch`（浏览器每 30s 调用），filter 在 Touch 上校验 epoch/exp 后 `AbortConnection`，管理台连接才能被及时踢掉。

**D8 扫码审批推送按会话归属隔离，轮询降级为兜底。**
QR 会话已带 `app_key/machine_code/install_guid`（R0 §3.6）。审批结果改为：devices Hub 对应 installation 组（客户端）+ admin Hub（管理台审批页）。`Clients.All` 删除。客户端 2s 轮询降为 10s 兜底（仅防推送丢失），管理台 5s 轮询由事件驱动替代。

**D9 管理台实时化：AdminHub + 事件驱动 invalidate + 低频兜底。**
- 分组按权限域：连接时按令牌 `perms` 声明加入 `domain:devices / domain:identity / domain:versions / domain:licensing` 等组；事件只发对应域组。事件负载带 `appKey`，前端按当前应用上下文过滤后再 invalidate（推送只是提示，回拉仍受服务端权限门禁，双保险）。
- 浏览器 SignalR 客户端用 `accessTokenProvider` 走查询参数令牌：`AuthenticationSetup` 的 query token 放行路径从仅 `/hubs/devices` 扩为 `{/hubs/devices, /hubs/admin}`。
- 前端统一 `AdminHubConnection` provider（自动重连 + 退避），各页订阅事件 → `queryClient.invalidateQueries`；保留 60s 兜底 refetchInterval 防事件丢失，删除 5–15s 高频轮询。

**D10 单副本约束不变，水平扩容列为后续独立批次。**
本轮所有新状态（停用标记、事件路由）仍放进程内登记表，与 `SingleInstanceGuard` 一致。扩容路径（Redis SignalR 背板 + 分布式连接登记表/Ack 表 + Webhook 行级认领）写入 §10 备忘，不在本轮范围。

**D11 测试期零兼容包袱（2026-11-18 用户确认）。**
平台与客户端均重新部署/安装，无存量生产现场程序或设备。因此：不留兼容分支与迁移窗口；不做「旧包共存不破坏」设计与验收；零消费方的通道/契约（PlatformHub 及其 DTO/常量）直接删除；契约破坏性变更由客户端同批更新 pin 消化；库结构变更沿用 R0-D13 单基线 + 删库重建。各事件仍保留**非推送兜底路径**（重连对账/低频轮询）——那是可靠性设计，不是兼容设计，两者不混淆。

| `UserSessionRevoked` | `UserSessionRevokedNotification(AppKey, UserId, InstallGuid?, SessionId?, Reason, OccurredAt)` | installation 组（可定位时）/ app 组（用户级全吊销） | 客户端比对本地会话归属，命中则登出 |

约定：新增 DTO 一律带 `OccurredAt`（服务端 UTC），供客户端去重/去抖与诊断；`LicenseChangedNotification / ReleasePublishedNotification / DocumentChangedNotification` 移入 Devices 契约、`QrLoginApprovedNotification` 移入 Identity 契约（D11 零兼容，`PlatformHubs.cs` 整体删除）；`DeviceHubEvents.StateChanged` 预留项删除（管理侧状态事件走 AdminHub，避免两处定义）。

### 4.2 AdminHub 契约（新增 `Hubs/AdminHubContracts.cs`）

- 路径 `/hubs/admin`；分组 `AdminHubGroups.Domain(string)` → `domain:{devices|identity|versions|licensing|apps}`。
- 上行：`Touch`（无负载；浏览器每 30s 调用，承载 epoch/exp 校验与服务端踢线，D7）。无其它业务方法；negotiate + 连接即入组。
- 下行事件：

| 事件 | 负载要点 | 触发点 |
|---|---|---|
| `InstallationStateChanged` | appKey、installationId、nodeId、onlineStatus、stationStatus、alarmLevel | `InstallationPresence` 心跳/断开/离线扫描落库后 |
| `NodeStateChanged` | nodeId、聚合在线/运行/报警 | 同上（聚合变化时） |
| `LicenseChanged` | appKey、machineCode、reason、entitlementId | 签发/续期/吊销 |
| `QrSessionChanged` | appKey、sessionId、status | 创建/审批/拒绝/取消/过期 |
| `ReleaseIngestionProgress` | appKey、packageId、status、progress | 摄取 Worker 状态迁移 |
| `UserSessionsRevoked` | appKey、userId、count | 管理端吊销会话 |

所有事件同样只是提示：前端收到后 invalidate 对应 query，事实以回拉为准。

> 实现偏差（W4 定案）：`LicenseChanged` 负载不含 `entitlementId`，管理台按 `['licensing']` 前缀失效回拉即可，不为提示性负载加列（避免破坏性契约变更）；`QrSessionChanged` 的 `expired` 迁移是读侧惰性判定、不发事件，创建/取消/审批/拒绝四类真实写事务各推一条。

### 4.3 PlatformHub 删除清单（D2/D11）

- 删除 `PlatformHub` 本体、`Program.cs` 的 `MapHub<PlatformHub>`、`PlatformHubPaths / PlatformHubGroups / PlatformHubEvents` 常量。
- 删除 `ConfigPushNotification / ConfigPushAck` DTO（devices Hub 已有 `DeviceConfigPush / DeviceConfigPushAck`，广播改道后复用后者）。
- `LicenseChanged / ReleasePublished / DocumentChanged / QrLoginApproved` 通知 DTO 移入各域契约（§4.1 约定）；`PlatformHubs.cs` 文件删除。
- `PlatformPushCoordinator` 保留**广播回执等待**职责（`WaitForAckAsync/CompleteAck`，键 `(appKey, backupId)`，先到者胜语义不变），删除连接登记职责（`RegisterConnection/ConnectionCount`）；广播在线门禁改查 devices 连接登记表的该 app 活跃连接数。
- 三个发送方改道：Licensing → devices installation 组（D5）；QR → devices installation 组 + AdminHub（D8）；Backup `broadcastToApp` → devices app 组（§5.4）。
- 11-devices.md 同步改写：删除 `/hubs/platform` 章节与 `broadcastToApp` 走 platform Hub 的旧口径。

## 6. 客户端契约义务（老客户端 AppFrameworkCS，本轮只列要求）

1. **订阅新事件**：`ServerGateway` 已订阅 `ConfigPush/Restart/SessionReplaced`，增订 `LicenseChanged / ReleasePublished / DocumentChanged / PermissionManifestChanged / InstallationDisabled / NodeDisabled / UserSessionRevoked`。`LicenseChangedReceived` 事件与 `LicenseMonitorService` 的 200ms 去抖复检链路**已存在且为空订阅**（ServerGateway.cs:680 注释、LicenseMonitorService.cs:221-260），接线即通。
2. **重连对账**（D3 的兜底核心）：每次 `RegisterInstallation` 成功（含重连）后必做——回拉 `licensing/status`（现有 Online 触发复检已覆盖）；版本/文档/权限清单按各自现有「需要时拉取」语义不强制对账。断线窗口丢失的授权事件由此覆盖，6h 周期复检保留为最后兜底（可放宽到 24h）。
3. **停用处理**：收到 `InstallationDisabled/NodeDisabled` → 状态置 Disabled、UI 明示原因、停止激进重连（退避拉长到 ≥5min 或仅手动重试）；不得盲目抢连（与 SessionReplaced 既有纪律一致）。
4. **会话吊销**：`UserSessionRevoked` 比对本地用户会话归属（userId/installGuid/sessionId），命中则走既有登出清理；不命中忽略。客户端不配合也无妨：epoch 守卫 ≤30s 内令该用户全部访问令牌 401（D7），下次调用/刷新即被踢回登录。
5. **广播回拉抖动**：app 组广播事件触发的回拉加 0–5s 随机抖动，避免同 IP 多实例同时回拉撞限流（§10）。
6. **激活窗 30s 轮询**：G1 落地后可降为事件驱动 + 10s 兜底（管理端签发后不重启自动放行的体验不变，时效从 ≤30s 提升到 ≤5s）。
7. 新客户端 appframework-client：按 R0-D14 暂停接入；未来网关批次（W5 缺口「吊销 30s 内锁界面」）直接以本契约为准，令牌管理必须收口在 `PlatformSession` 串行门内（刷新令牌复用检测会吊销全会话）。

部署口径（D11）：平台与客户端同步重新部署/安装，无旧包共存场景；客户端新包与契约 pin 更新随 W1–W3 各批同交付，不做「旧包不破坏」验证。

## 7. 关键时序（文字版）

### 7.1 授权吊销（G1）

管理端吊销 → `LicenseEntitlementService` 落库 → router：machineCode→nodeId→登记表筛 appKey 活跃安装 → installation 组发 `LicenseChanged(revoked)` + AdminHub 发域事件 → 客户端 200ms 去抖 → 回拉 `licensing/status` → 验签快照判定降级（运行期只刷卡不打断在测工单，下次启动拦截——既有语义不变）→ 管理台 invalidate 授权页。目标端到端 ≤5s。

### 7.2 实例停用踢线（G2/G9）

管理端停用 → 落库 `IsEnabled=false` → 登记表打标 + installation 组发 `InstallationDisabled` → 客户端置 Disabled；即使客户端不配合，下一次心跳（≤10s）被 `DeviceHubGuardFilter` 检出标记 → 服务端 `AbortConnection` → 断线离线落库 → 客户端重连注册被拒（807）→ 长退避。节点停用同理走 node 组 + 节点级标记。

### 7.3 会话吊销（G3）

管理端吊销（单会话/用户全部/重置口令）→ bump `token_epoch` + 吊销刷新令牌家族 → devices Hub 定向发 `UserSessionRevoked` + AdminHub 域事件 → 配合的客户端 ≤5s 主动登出；不配合的客户端 ≤30s 内全路径 401（epoch 守卫缓存窗口），`/context` 换发与 QR 审批续期同被封死 → 管理台浏览器连接被 `Touch` filter 踢掉、HTTP 401 回登录页。

### 7.4 令牌过期（G9）

M2M 令牌 30min 到期 → 连接不中断（传输层 ping 正常）→ 下一次心跳被 filter 检出 `exp` 过期 → `AbortConnection` → 客户端监督循环换令牌（AccessTokenProvider 重连时取新）→ 重连注册 → 重连对账。被动断线窗口 ≤ 一个心跳周期 + 退避首档 5s。

### 7.5 管理台状态实时化（G8）

客户端心跳 → `InstallationPresence` 落库且状态值变化 → AdminHub `domain:devices` 组发 `InstallationStateChanged` → 前端按 appKey 过滤 → invalidate 节点/安装列表 query → React Query 回拉管理端端点（权限门禁不变）。60s 兜底轮询覆盖事件丢失。

## 10. 风险与边界

1. **回拉风暴与限流**：全局 600/min/IP，同一机器 3 应用共享 IP、NAT 后多机共享出口 IP。app 组广播 + 客户端 0–5s 抖动是第一步；若现场规模仍撞限流，再考虑服务端按 app 聚合提示或调分区策略（W3 验收时压测确认）。
2. **访问令牌残余窗口（D7 评审修订）**：原案「≤30min」被 `/context` 自续期漏洞证伪（§12）。引入用户级 epoch 守卫后，吊销即 bump epoch，已签发访问令牌在 ≤30s（守卫缓存窗口）内全路径失效，含 `/context` 换发、QR 审批、单次密钥签发；AdminHub 连接由 Touch filter 踢掉。不引入 jti 黑名单；缓存窗口 configurable，调小更实时但查库更频。
3. **推送丢失**：断线窗口、进程重启期间事件不补发（D3）。授权靠重连对账，管理台靠 60s 兜底，版本/文档靠需要时拉取——每个事件都必须有非推送兜底路径，验收矩阵逐条对应。
4. **nginx 空闲超时**：`/hubs/` 读写超时 3600s，SignalR KeepAlive 15s 保证不空闲；AdminHub 浏览器连接同样受 ping 保活。若现场另有更短超时的代理层，需同步排查。
5. **单副本**：新增状态全部进程内，`SingleInstanceGuard` 语义不变。用户 epoch 短缓存为进程内缓存（与 AppContextGuard 同模式），多副本下各自缓存、收敛时间仍 ≤ 缓存 TTL，无需共享存储。扩容前置条件（Redis 背板、分布式连接登记表/Ack 表、Webhook 行级认领）未满足前不得关闭 `Deployment:RequireSingleInstance`。
6. **AdminHub 信息暴露面**：域分组 + 事件只含 id/状态枚举不含敏感明细，回拉仍走权限门禁；perms 声明来自管理员令牌，与 HTTP 面同源。
7. **契约包缓存**：preview.2 重打本地 NuGet 包时，客户端若报 CS0234 先比对全局缓存时间戳（已知坑），必要时清缓存再 restore。破坏性变更（`PlatformHubs.cs` 删除、DTO 归位、`StateChanged` 移除、新增事件/`epoch` 声明）按 D11 不留兼容窗口，客户端 pin 同批更新、同步重装。
8. **心跳与传输保活职责**：业务心跳（10s，承载状态与离线判定）与 SignalR ping（15s，承载传输保活）并存，不可用其一替代另一；GuardFilter 的过期/停用检测搭载业务心跳，若客户端把心跳调到 3600s 上限，踢线延迟同步放大——文档化该关系，管理端停用踢线延迟以实际心跳周期为准。AdminHub 无业务心跳，由浏览器 30s `Touch` 承载 epoch/exp 检查，管理台踢线延迟 ≤30s + 守卫缓存窗口。
